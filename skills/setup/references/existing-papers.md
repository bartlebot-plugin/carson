# Papers the user already has

Many people come to Carson with a folder of household papers already. Setup asks about it once, straight after "Where the papers will live," and before any folder is built.

## The question

**Ask:** "Do you already keep household papers in a folder, on this computer or in your Drive?"
- No, I'm starting fresh. (default)
- Yes, and I like how it's organized. Keep it as it is.
- Yes, but it's a mess. Organize it for me.

Record the answer in `_system/settings.md` as `storage.layout`: `carson`, `own`, or `carson` with `storage.old_folder` filled (the third choice). On "starting fresh," carry on with the ordinary interview and read no further here.

Say once, on either "yes": "Whichever you choose, I won't delete, rename, or move anything you already have."

## Keep it as it is

Carson works inside the user's own folder and files new papers into their layout. Nothing already there is moved, renamed, or changed, at setup or later.

**Getting to the folder.**
- Folder mode: their existing folder must be the one attached to this conversation. If a different (empty) folder is attached, ask them to choose their existing folder instead and say "set up Carson" again.
- Drive mode: ask what the folder is called, find it, and confirm it by naming two or three things inside it. If two folders have that name, ask which. That folder becomes the Carson folder; do not create a new one.

**Looking at it.** List the folder names two levels down, with a rough count of files in each. Read names only; open no documents. Skip anything that is plainly not household paper (photo libraries, music, program files) and say so in one line.

**Step 3 changes.** Do not offer the folder menu. Instead:

1. Say back how the folder reads, in a short list using their folder names: "Here is how I read your folders," one line each with a few words on what seems to go there.
2. Ask "Have I got that right?" and take corrections.
3. For a folder whose purpose is not clear from its name and contents, ask what goes in it, one at a time, five at most. Any still unclear are recorded as "ask before filing here."
4. For each kind of paper in `folder-menu.md`'s starting set that has no home in their layout, ask once whether to add a folder for it, naming the folder: "You don't seem to have a place for tax papers. Shall I add a folder called Taxes?" Add only on a yes.

**Building.** Create Carson's fixed folders (`_inbox`, `_processed`, `_system`, `Reference`, and their subfolders) alongside what is there. If the user already has a folder called "Reference," do not use it or touch it: make Carson's own as "Carson reference" and record that name in the settings note as `storage.reference_name`. (The other fixed folders begin with an underscore and will not clash.) Write the filing protocol's "where things go" lines from their real folders. Write one index note per topic that has papers, as usual; they start empty.

**Names.** New papers Carson files are named Carson's way (date, description, person). Say so once. Existing names are never changed.

**What is already there** has no notes yet. Do not read through it during setup. At the wrap-up, add one line: "I haven't read the papers you already had. When you'd like me to, say 'go through my Insurance folder,' or any folder, and I'll note what matters." That is the bring-in skill's "going through a folder."

## Organize it for me

Carson builds a new Carson folder in the ordinary way and copies the old papers into it. The old folder is never changed; it stays as the user's safety copy until they choose to delete it themselves.

**Getting to both folders.**
- Folder mode: the new, empty Carson folder is attached as usual. The old folder must be reachable too: ask the user to add it to this conversation as a second folder. If it cannot be added now, carry on with setup and bring the papers in later.
- Drive mode: ask what the old folder is called, find it, and confirm it as above. Create the new Carson folder as usual; never build inside the old one.

Record where the old folder is as `storage.old_folder` (its name, and in Drive its ID).

**Step 3 changes.** Before proposing folders, look at the old folder's names two levels down (names only). Use what is there to shape the starting set: add a menu topic when the old folder plainly holds that kind of paper, and offer a folder of the user's own when a large group fits no menu topic. Then ask "Shall I start with these?" as usual.

**The copying itself is not part of setup.** It can take a long time and is done in batches by the bring-in skill. Finish setup first. At the wrap-up, after the usual words, ask: "Shall we start bringing in your old papers now, or another time?" On "now," run the bring-in skill. On "another time," say: "Whenever you're ready, say 'bring in my old papers.'"
